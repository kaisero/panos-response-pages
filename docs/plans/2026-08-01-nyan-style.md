# Nyan Runway: a seventh style, with a palette of its own

Turn the `tmp/nyan-lab` draft into a shipped style: a pixel cat crossing a night
sky beside the notice, laying the rainbow trail it is known for. Unlike the six
brand styles, this one owns its colour — it ships a palette and pins it — which
means the build gains a mechanism it does not have today.

The draft proved the layout, the artwork and the byte cost across all nine block
pages and all six portal surfaces, in both schemes, at desktop and mobile widths.
What it did not do is fit the test suite, and that is most of the work below.

## Decisions taken (interview, 2026-08-01)

| # | Decision |
|---|---|
| 1 | A theme may **pin a palette** — `"palette": "nyan"` in the theme JSON |
| 2 | Precedence: **`--palette` → customer config → theme pin → built-in default** |
| 3 | Config only counts as a choice when the **customer file** set it, not `_defaults.json` — resolved by tracking provenance in `config.py` |
| 4 | Palettes gain **`kind: "brand" \| "style"`**; the dark-ground saturation guard applies to brand palettes only |
| 5 | Block pages ship **CSS artwork + ~300 B of steering JS** — no canvas, no runtime sprite builder |
| 6 | The GlobalProtect imports get **no cat**: sky, stars, glass card, and the rainbow reduced to a hairline on the card edge |
| 7 | The cat flies on **every block page regardless of tone**; tone drives the pill, mark and glow only |
| 8 | Light scheme is a **dusk sky** — deeper than the draft's lavender, dark ink still readable |
| 9 | Artwork is a **literal in both shells**, generated by a checked-in script, with a **drift test** |
| 10 | The style ships as **`nyan`** with the recreated sprite — see *Accepted risk* |
| 11 | Docs: fix every stale count, **document style palettes**, add a test that `styles.md` lists every theme. CHANGELOG under `## [Unreleased]` |

### Accepted risk

Nyan Cat is a specific copyrighted character and trademark, and the sprite is a
close recreation shipped under that name in an MIT package on PyPI. This was
raised, weighed and accepted by the repository owner. It is recorded here so it
is visible to anyone who works on this later rather than buried in a chat log.

Decision 9 is what keeps it cheap to revisit: the artwork exists as one compiled
string produced by one generator and asserted in two places, so replacing the
character is a contained change — new pixel map, regenerate, two literals, one
test. Nothing else in this plan depends on what the thing at the head of the
trail looks like.

## Two mechanisms the build does not have yet

### Style palettes

`palettes.py` states the axis: *a theme owns layout, a palette owns colour*. Six
themes × three brand palettes is the matrix that split buys. `nyan` breaks it on
purpose — a nyan trail in house cyan is not a nyan trail — so the palette gains a
declared kind:

```json
{ "name": "nyan", "kind": "style", "label": "Nyan Pink", ... }
```

`brand` is the default for the existing three. The only behavioural difference
today is that `test_dark_grounds_are_tinted_not_saturated` skips style palettes:
its rationale is that a *brand* hue must stay a whisper in a dark UI, and nyan's
ground is artwork rather than a tinted neutral (it is 44% saturated against a 22%
cap; `d_surface` 50%, `d_surface_alt` 43%). Scoping the guard by kind keeps the
rule and its reason in the data, so the next style palette needs no test edit.

### A theme that pins its palette

Today `build_all` resolves one palette **before** the theme loop
(`builder.py:148`) and hands it to every page. It has to move **inside** the
loop, because the answer is now per theme.

Resolution order, first hit wins:

1. `--palette` on the command line
2. `palette` set in `config/<customer>.json` — the customer's own file, not the defaults
3. `palette` in the theme JSON
4. `cfg["palette"]`, then the `"cyber-orange"` literal

Step 2 is why provenance matters. `config.py` deep-merges the customer file over
`_defaults.json`, and `_defaults.json:5` always sets `"palette": "cyber-orange"`
— so `cfg["palette"]` is populated on every build and, taken at face value, would
outrank the pin in all cases and render nyan cyber-orange. The merged config must
therefore be able to say *where* the value came from.

Shape: `load_config()` keeps returning the merged mapping and gains a companion
`customer_keys(customer, config_dir) -> set[str]` that reads only the customer
file's own top-level keys. `builder.py` asks it once per build.

Consequences to handle rather than discover:

- `BuildResult.palette` is a single palette used by the report footer and by
  `build_gallery()` for the gallery's own chrome. Keep it as the **build-level**
  palette; the gallery inlines each page as `srcdoc` with its own CSS, so a theme
  rendering in its own palette needs nothing from the gallery.
- `PageResult` / `PortalResult` gain the palette actually used, and
  `format_report()` names it wherever a theme differs from the build-level one.
  A style quietly rendering in a colour nobody asked for is exactly the class of
  silent failure this project exists to catch.
- The portal family resolves the same way — `build_portal_page()` already takes
  a palette argument, so it is one call site, not a second mechanism.

## Phase 1 — the palette

**Files:** `data/palettes/nyan.json`, `data/palettes/{cyber-orange,strata-yellow,prisma-blue}.json`, `tests/test_palettes.py`

1. Add `"kind": "brand"` to the three existing palettes; `"kind": "style"` to nyan.
2. Port the draft palette, then **re-tune the light scheme to dusk** (decision 8).
   The draft's `#f7f5ff` becomes a deeper violet; ink stays dark. Every light-side
   pairing moves with it, so re-run the contrast pass — `accent_text`, `warn_text`
   and `crit_text` will likely need darkening.
3. Verify with the suite's own maths before running the suite: all 18 tokens plus
   their `d_` twins, `^#[0-9a-fA-F]{6}$`, accent identical to the ramp's 500 stop,
   gradient 500 → 1000, and **16 contrast pairs per scheme at ≥ 4.5:1**.
4. `test_palettes.py` edits:
   - `expected` in `test_palettes_match_their_declared_ramps` gains nyan's five
     stops — **this is the one hard failure**, it raises `KeyError` otherwise.
   - `test_the_three_palettes_exist` gains `nyan` and a name that is not a lie.
   - `test_dark_grounds_are_tinted_not_saturated` skips `kind == "style"`, with
     the reason in the docstring.
   - New: every palette declares a `kind`, and it is one of the two values.

**Verify:** `uv run pytest tests/test_palettes.py -q`.

## Phase 2 — pinning

**Files:** `config.py`, `builder.py`, `data/themes/nyan.json`, `tests/test_config.py`, `tests/test_build*.py`, `tests/test_cli.py`

1. `customer_keys()` in `config.py`.
2. Move palette resolution into the theme loop in `build_all()`; add the
   precedence chain; carry the chosen palette on each result row.
3. `format_report()` names the palette per theme where it differs.
4. `themes/nyan.json` gets `"palette": "nyan"`.
5. Tests, one per rung of the ladder: pin honoured when nothing else speaks;
   customer config beats the pin; `--palette` beats both; `_defaults.json` alone
   does **not** beat the pin (the regression this whole mechanism exists for);
   the report names the palette for a pinned theme.
6. `tests/test_cli.py` — add `nyan` to the theme tuple in
   `test_themes_lists_every_style_with_its_label` and to both palette tuples
   (`test_palettes_lists_every_palette`, `test_unknown_palette_reports_what_is_available`).

**Verify:** `uv run pytest -q`, then `uv run panos-response-pages build` and
confirm the report shows nyan in Nyan Pink and the other six in the build palette.

## Phase 3 — the block shell

**Files:** `data/templates/shells/nyan.html`, `tests/_nyan_sprite.py`, `tests/test_nyan_sprite.py`

The draft shell is the starting point, with the canvas removed. Composition:
night/dusk sky, drifting CSS starfield, glass card held out of the flight lane,
cat + stepped rainbow crossing a band, pointer steering as progressive
enhancement.

**The 21-rule shell contract** (`tests/test_shells.py`, parameterised over the
shells glob — a new shell is picked up automatically). The draft already
satisfies most of it. The ones it does **not**, or that need care:

- **`@media(max-width:600px)` must appear literally.** The draft's breakpoints are
  820 and 1100; the 600 block has to exist in its own right.
- **The four `:root` blocks must declare identical token sets.** `--sky`, `--star`
  and `--veil` are nyan's own and must appear in all four, `:root` a superset.
- **`.btn` must not vary with severity** — no `var(--tt)`/`var(--tw)` in it. The
  draft's accent glow uses `var(--ac)`, which is fine.
- **`color-mix` needs a solid declaration of the same property immediately
  before it.** Draft does this for `.btn`'s `box-shadow` and the cat's `filter`.
- **`radial-gradient` is texture-only**: the rule must carry `background-size:` or
  `mask-image:` and must not set `color:`. The starfield qualifies.
- **`.sev:empty{display:none}` after the rule that paints `.sev`.**
- `{{FACTS}}` inside a literal `<dl>`; `id="gloss"` immediately wrapping
  `{{GLOSS}}`; `{{SCRIPTS}}` after FACTS/ACTIONS/EXTRA; `{{EXTRA}}` at most one
  container level out from `{{ACTIONS}}`; all 12 placeholders rendered.
- `.plain`, `.note`, `.infobox`, `.warnline` styled; `.plain a` / `.note a` take
  `var(--at)`; `dd` carries `overflow-wrap:anywhere`; `.acts` styles the injected
  `input[type=submit]` and `button`; reduced-motion opt-out.

**The landmine the draft hit:** the emitted script resolves the Category row with
`document.getElementById('cat')`. The sprite element must **not** use `id="cat"`
— the draft renamed it `ny`. Getting this wrong silently retargets the
category-driven tone and gloss rewrite at a decorative div.

**Artwork:** `tests/_nyan_sprite.py` holds the readable pixel map and compiles it
to the merged-rectangle path SVG (~1.7 KB); the compiled string is pasted into
both shells. `tests/test_nyan_sprite.py` regenerates and asserts both copies
match exactly. Rectangle merging is not an optimisation detail — per-pixel rects
are 10,935 B and do not fit either family's ceiling.

**Interaction (~300 B, progressive enhancement):** `pointermove` writes a custom
property the flight reads; click bumps the animation. No JS, no interaction, and
the flight still runs on CSS alone.

**Verify:** `uv run pytest tests/test_shells.py -q`, then look at the gallery in
both schemes at desktop and mobile — the draft's contact sheets
(`tmp/nyan-lab/sheet.png`) are the reference for what "right" looks like.

## Phase 4 — the portal shell

**Files:** `data/templates/portal/shells/nyan.html`

Mandatory, not optional: `test_portal_shells.py::test_shells_exist_for_every_theme`
asserts the portal shells and the block shells are the same set, so this fails the
suite the moment `shells/nyan.html` lands without it.

No cat here (decision 6). Sky, stars, glass card, pink accent, and the rainbow as
a fine 6-stripe rule on the card's top edge. Slots stay split — `STYLE_LOGIN`,
`BODY`, `STYLE_LOGOUT` — for the byte reason `portal/page.py` documents.

Rules specific to this family:

- **No raw `<` outside a tag** (`portal/validate.py`) — it stops PAN-OS
  substituting the form token. It is why this family gets no scripted sprite:
  every `i<n` comparison would trip it.
- `<pan_form/>` exactly once, and never inside a comment.
- All six `LOGIN_VARS` / fourteen `HOME_VARS` declared; `id="logo|activearea|heading|formdiv"` present.
- Logo painted from CSS with both scheme copies (`--lgl`, `--lgd`), `#logo img{display:none}`.
- `#logout` reserves `min-height`; the `#dChangePasswordMsgArea .msg` selector stays banned.
- The download widget keeps its ids, its `html[data-dl]` rules, `.dlcar:focus-visible`
  outline and `#taGetSofewarePage p a` padding — `tests/test_portal_download.py`
  checks all of it per theme.
- No `overflow:hidden` on `html`/`body`; `overflow-x` is fine and is what keeps the
  200vw trail from adding a scrollbar while leaving the change-password state
  scrollable.
- Ceilings: 16,170 B raw / 21,845 encoded. The draft's cat-bearing login was
  14,351 B; without the cat this lands lower.

**Verify:** `uv run pytest tests/test_portal_*.py -q`, then all six preview
surfaces in both schemes.

## Phase 6 — verification

```bash
uv run nox                                        # lint, types, tests, docs
uv run panos-response-pages build                 # every style, every page
uv run panos-response-pages validate out/deploy   # guards over real output
open out/preview/index.html
```

Expected: `styles × pages` files checked, `0 would fail`, every nyan page under
16,000 B (the suite's own limit, tighter than the 17,999 B ceiling), both portal
imports inside 16,170 B, and the report naming Nyan Pink for nyan alone.

By eye, in the gallery: both schemes, desktop and mobile, and specifically the
two `url-*` pages (heaviest), `credential-block-page` (crit tone, `COPY_LOCK`),
`safe-search-block-page` (no category row, so no tone repaint) and
`file-block-continue-page` (PAN-OS injects a form into `.acts`).

## Byte budget

The draft with canvas and runtime sprite reached 16,582 B on `url-block-page` —
over `tests/test_shells.py`'s 16,000 B limit, so it would have failed the suite
rather than merely warning. CSS artwork plus the steering script costs roughly
2.5 KB over a plain shell instead of 5.1 KB, which lands the heaviest page near
13.5 KB. Confirm the real figure at the end of Phase 3; if it creeps over
15,000 B, the starfield is the first thing to simplify.

## Risks and open items

- **The dusk light scheme is unproven.** Moving the light ground invalidates the
  draft's contrast pass; budget a round of tuning, and check the rainbow still
  reads against it.
- **`backdrop-filter`** carries the glass card's legibility. Without it the veil
  alone has to hold, which is why it sits as high as it does — check one browser
  without support before calling Phase 3 done.
- **Byte headroom** on the two `url-*` pages is the tightest constraint in the
  style and the first casualty of any addition.
- **Interaction on a crit page.** Decision 7 keeps steering and boost on the
  phishing and malware pages. Recorded as deliberate; if it reads wrong in
  review, disabling play at `data-tone=crit` is one CSS rule and one guard.
